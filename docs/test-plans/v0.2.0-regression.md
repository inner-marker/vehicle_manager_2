# Regression checklist: `v0.2.0`

*The `v0.2.0` release plan (`docs/phase_plans/phase-2.md`), question 2 · plan §9 "Before a release, the relevant plans are re-run as a manual regression checklist" · decisions #062, #070*

A short pass through every Phase 2 milestone, on the **test server** with the **`:dev`** image, **after the release PR (`chore: release v0.2.0`) has merged into `dev`** and before the PR from `dev` into `main`. It doesn't re-run the milestone plans; it checks that each milestone's main path still works together. A failure is fixed on `dev` (and the pass run again) before anything reaches `main`.

## Setup

- **The image:** the "Dev image" run for the release PR's merge finished successfully (Actions).
- **On the NAS over SSH,** the test server's folder:

  ```sh
  cd /volume1/docker/vehicle_manager_test
  vi .env
  ```

  Set `VEHICLEMANAGER_IMAGE_TAG=dev` and leave `VEHICLEMANAGER_TEST_MINUTES=` empty. Then `Esc`, `:wq`.
- **People:** `admin`, Sam (Driver), and `vera` (Viewer, from milestone 9).
- **Devices:** the phone's browser and the Mac's.
- **The main server is untouched** until the release is tagged.

## If a step fails, capture

- **Container logs:** `sudo docker logs --since 30m vehiclemanager-test 2>&1`.
- **The step's number,** a screenshot, the device and browser, and who was signed in, in which mode.
- **Never share** a password, `.env`, a cookie, or a document with personal details on it.
